Features

Everything your firmware workflow needs

From analysis to repack — every operation runs on-device inside a project-based workspace.

Payload Dumper

Unpack & repack payload.bin OTA firmware with the payload-dumper-go engine.

Super Image

Unpack & repack super.img — sparse-aware conversion handled automatically.

Filesystem

Extract & repack EROFS/ext4 images with mkfs.erofs, debugfs and make_ext4fs.

Boot Family

Unpack & repack 7 boot image types including vendor_boot with magiskboot.

Firmware Analysis

Metadata-only parsers with health score, validation & recommendations — safe for 8–10+ GB images.

Workspace Projects

Every task runs as a project — create, resume, rename, delete, with chronological operation history.

Firmware Inspector

Dashboard with StatusPanel, WorkspaceCard, QuickMetrics and a live, always-animated status card.

AFFT Manager

Device file browser with search, sort, multi-select, copy/move, delete, rename, properties & import.

Premium Appearance

6 theme presets, custom accent & icon colors, dynamic color, custom fonts (Inter & JetBrains Mono).

Languages

English (default) and Bahasa Indonesia — persisted across restarts.

Interactive Metadata

Long values (paths, hashes, fingerprints) open a bottom sheet with copy, share & open-folder actions.

Console & Logs

Real-time output in the sidebar, debug mode, and a log recording toggle.

How it works

Three steps to a repacked ROM

Pick your firmware

Open Payload, Super, Filesystem or Boot, then select a file from the device or import it via AFFT Manager.

Analyze or unpack

Let the parsers read metadata instantly, or unpack the image into your workspace project.

Modify & repack

Edit what you need, repack the image and export it to Download/AFFT.

Workspace

Project-based, resume-friendly

Every operation belongs to a project so you can always continue where you left off.

workspace/
└── <ProjectName>/
    ├── metadata.json  ← project info, device, firmware type, health score
    ├── logs/            ← operation logs
    ├── output/           ← extracted / exported results
    ├── temp/             ← working files
    ├── cache/            ← cached data
    ├── payload/          ← payload.bin work area
    ├── boot/              ← boot images work area
    ├── super/            ← super.img work area
    ├── filesystem/        ← filesystem work area
    ├── apk/               ← APK work area
    └── reports/           ← analysis reports
Requirements

What you need

RequirementDetails
Android8.0+ (API 26)
ArchitectureARM64 only
RAM4 GB minimum (6 GB+ recommended)
StorageAt least 10 GB free for large firmware files
PermissionsMANAGE_EXTERNAL_STORAGE, foreground service, POST_NOTIFICATIONS
Privacy

Your data stays on your device

Working files, workspaces and deployed binaries are excluded from Android Auto Backup & device transfer. Firmware images are never uploaded to cloud backup.
